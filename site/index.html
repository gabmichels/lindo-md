A Markdown viewer that makes documents worth reading.

Local .md files usually open in a plain-text editor or a previewer that looks like a 2014 admin panel. lindo-md renders them the way a well-set page should look — and lets you edit the page you are reading without switching into a source view first.

What it renders

Everything GitHub renders — and one thing it doesn't.

The panel below is not a screenshot. It is a page on this site, drawn with the theme you have selected, so you can judge the type before you download anything.

Reading a document

Body text is set in Source Serif 4 at a sixty-six character measure — the same page the app opens with. Emphasis is drawn, not slanted, links are underlined rather than merely coloured, and inline code sits in the line instead of on top of it. Footnotes work1, and so do [[wikilinks]], which GitHub has never rendered.

Note

All five GitHub alert kinds are supported, and the kind is written into the callout in words — so a reader who cannot see the hue still knows which one this is.

// A preset is an opinion, not a cage.
export function applyTheme(theme: Theme, mode: Appearance) {
  const half = mode === "dark" ? theme.dark : theme.light;

  for (const [token, value] of Object.entries(half.palette)) {
    canvas.style.setProperty(`--doc-${token}`, value);
  }

  // Custom properties inherit, so the nearest themed ancestor wins.
  return true;
}

Features

Built to be lived in, not looked at once.

Edit in place

Type directly into the rendered page. There is no mode to enter and no Save to remember — the Markdown file is the source of truth, and a write is refused if the file changed underneath you.

Tabs and tab groups

Contiguous, coloured, collapsible groups. Every tab keeps its own scroll position and history, and the whole session comes back on launch.

Twenty themes, all editable

Every preset ships a light and a dark half, its own type and its own page furniture. Thirteen colours, eleven type controls, and the result exports to a JSON file you can share.

Two documents at once

A read-only comparison pane at a fixed half of the canvas — Ctrl \, or drag a tab into the right half and it opens there.

A real folder, not one file

File tree, "On this page" outline, reading progress, find, zoom and live reload. Every Markdown dialect opens like .md; plain text opens read-only and the window says so.

Export and print

HTML export that carries the theme with it, and print-to-PDF that sets the page rather than screenshotting the window.

Themes

Pick one. The whole page changes.

These are the app's twenty presets, and this is what they do — the site is re-themed live, including the document above. Colour is only half of it: in the app each preset also brings its own type, measure and page furniture, which a single web font cannot show.

Privacy

One request, and it is optional.

Remote images are blocked by default, so opening a document cannot report that you did. Shiki, KaTeX and Mermaid are bundled, not fetched. The launch version check is the only thing that reaches the network, and it has a switch — turn it off and the app opens no connections at all.

It is a small native desktop app built on Rust and Tauri, using the WebView your system already has, rather than an Electron shell shipping a second browser.

Network activity

Version check on launch — Settings → General to disable.

Download

Free, MIT licensed, no account.

Installers are published on GitHub with every release.

Windows

  • lindo-md_x64-setup.exe
  • lindo-md_x64_en-US.msi

Associates the Markdown extensions, so Open with → lindo-md works. Text files are opened but never claimed, so your own editor keeps them.

Linux

  • lindo-md_amd64.AppImage
  • lindo-md_amd64.deb
  • lindo-md.x86_64.rpm

For the AppImage, chmod +x it first. The .deb and .rpm register the desktop entry and file associations.

macOS

No published build. It compiles fine, but an unsigned bundle fails Gatekeeper with "lindo-md is damaged and can't be opened" — which reads as a broken download rather than a security prompt. Building from source sidesteps it, since a binary you compiled locally was never quarantined.

These builds are unsigned, so Windows SmartScreen will show "Windows protected your PC" the first time — choose More info → Run anyway. Instead of a code-signing certificate, every release publishes SHA256 checksums, a CycloneDX SBOM, and signed build provenance tying each binary to the exact commit and workflow run that produced it:

gh attestation verify <file> --repo gabmichels/lindo-md

docs/signing.md explains what unsigned costs you, what signing would cost, and why it has not been done — a decision on the record rather than an omission.

Build from source — Node ≥ 22.13, pnpm 11 and a stable Rust toolchain: 

$ pnpm install
$ pnpm tauri dev      # run
$ pnpm tauri build    # bundle
